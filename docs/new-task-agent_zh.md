# 新任务的 Agent 脚本生成流程

输入是用户的语言目标和代表性视频。若输出还要用于机器人训练，必须同时提供
实际记录的 action/state、各路相机和机器人标定；不能只凭视频编造关节数据。
详细模块路径和英文版步骤见 [new-task-agent.md](new-task-agent.md)。

## 1. 明确目标

填写[任务模板](../examples/task-brief.md)：物体、左右臂分工、初末状态、完成条件、
允许重叠的动作，以及必须保留的跨臂依赖。目标有歧义时先与用户讨论，例如
“拿住瓶子”和“放入托盘并松开”是不同任务。保持源文件不变，记录哈希和 FPS。

## 2. 观察视频，形成证据表

Agent 按时间观察接近、抓取、搬运、释放、撤回，以及遮挡和接触转换。为每个事件
记录帧区间、手臂、物体、可见证据与不确定性。语言提供意图，视频提供实际发生
的证据；不要用其中一个悄悄覆盖另一个。不能确认的释放事件应暴露给用户复核。

## 3. 复用代码，生成适配器与运行脚本

先读 `main.py` 和包中的 `interaction/`、`tasks/`、`timeline/`、`compositing/`。
任务语义完全匹配时复用已有 profile；新任务需要检查识别、调度、合成和数据导出
中的任务分支。只添加一个 profile 字典并不能打通整个管线。

生成小而明确的任务适配器和运行脚本，输入、输出、工作目录均用参数传入。
复用现有时间轴、平滑、合成与重映射逻辑，不复制整套管线。自动数据导出器目前
固定使用抽屉任务，不要把新任务伪装成 `drawer` 来绕过约束。

## 4. 规划时间轴并验证

左右臂源时间必须单调，保持操作顺序、接触和必要等待。显式编码“先打开再放入”
“先撤回再关闭”等依赖；等待位置必须适合持物。使用现有平滑代码，并在平滑后
重新检查整个运动过程。二维检查和标定后的三维检查必须分别报告。

## 5. 合成并同步数据

主视角按物体归属和遮挡关系合成；抓取后不能在原处复制出第二个物体，释放后
要转移场景归属。每只手的 action/state 和腕部视频采用同一源时间轴。保留源
episode、源索引、插值和合成静止帧标记。IdleMask 需要按任务语义定义，不能
把所有重复帧都当成不需要监督的 idle。

## 6. 验收与交付

先运行针对新约束的测试及现有回归测试，再处理一个真实片段并逐段检查画面。
验证任务目标、时序依赖、物体归属、相机与数值对齐、完整帧数及碰撞检查范围。
统计必须针对声明的训练有效行做全局计算，不能平均各 episode 的分位数。

交付：脚本与命令、任务配置/适配器、测试、预览、证据与验证报告。冻结来源、
配置、模型和代码哈希后再扩展至整个数据集。缺失证据应报告为未验证或失败，
不能用“脚本成功运行”代替结果正确。
